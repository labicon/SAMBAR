# Setup

Run commands from the repository root. Training targets Linux with NVIDIA GPUs and Python 3.11/3.12; all-parameter π0.5 plus optimizer and SAMBAR state requires substantial GPU memory. Use `--fsdp-devices` to shard across the selected devices. No hardware robot connection is needed.

## Training environment

Install [uv](https://docs.astral.sh/uv/getting-started/installation/), then:

```bash
uv sync --frozen --extra cuda
uv run --extra cuda python scripts/train.py --help
```

Use `--extra cuda` on GPU training invocations. CPU checks can use `uv sync --frozen` followed by `uv run pytest`. The lockfile preserves the source JAX 0.5.3, Flax 0.10.2, Optax 0.2.4 and Orbax 0.11.13 stack. LeRobot is pinned to source revision `0cf864870cf29f4738d3ade893e6fd13fbd7cdb5`.

Base model parameters load from `gs://openpi-assets/checkpoints/pi05_base/params` through the original downloader. Keep sufficient local disk space for the model, data, optimizer checkpoints and importance arrays. `OPENPI_DATA_HOME` can redirect the model cache; `HF_LEROBOT_HOME` can redirect the dataset cache.

The data loaders use these existing LeRobot datasets:

| Dataset | Role |
| --- | --- |
| `physical-intelligence/libero` | 40 tasks; narrow curriculum and new-task data |
| `jesbu1/libero_90_lerobot` | The additional 90 broad-pretraining tasks |

They download through the pinned LeRobot implementation when not cached. `--libero90-root ROOT` specifies a separate cache parent containing `ROOT/jesbu1/libero_90_lerobot`. The two repositories keep their own task-index tables. Task language, rather than cross-repository numeric IDs, identifies tasks.

The checked-in normalization statistics live under `assets/sambar/{narrow,broad}`. To recompute them with the same preprocessing/sampler:

```bash
uv run --extra cuda python scripts/train.py --mode norm_stats --setting narrow --exp-name norms
uv run --extra cuda python scripts/train.py --mode norm_stats --setting broad --exp-name norms
```

## LIBERO simulator environment

```bash
bash scripts/setup_libero.sh
export MUJOCO_GL=egl
```

The script clones [LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO) into ignored `third_party/libero`, checks out `8f1084e3132a39270c3a13ebe37270a43ece2a01`, and installs it into `examples/libero/.venv`. Set `LIBERO_SOURCE` to use a separate clean checkout. The simulator uses its own pinned dependencies to avoid mixing its Torch version with the training environment.

Initialize LIBERO's paths once in an interactive terminal:

```bash
examples/libero/.venv/bin/python -c 'from libero.libero import benchmark'
```

Follow upstream's path prompt, if shown, and ensure the resulting `~/.libero/config.yaml` points to that checkout's BDDL files, init states and assets. Evaluation uses those simulator assets; it does not require demonstration downloads. Training demonstrations come from the LeRobot datasets above. For raw demonstrations, follow the upstream download instructions instead of vendoring them here.

## Evaluation

```bash
uv run --extra cuda python scripts/evaluate.py \
  --checkpoint checkpoints/sambar_narrow/sequence/stage3/29999 \
  --setting narrow --task-ids 3 8 11 --output outputs/sequence-stage3
```

The driver starts the policy server, runs the retained LIBERO evaluator in its separate environment, and writes raw per-task results plus a per-seed summary. It matches language strings to avoid mixing LeRobot and simulator task index orders. Defaults are seeds 1–5, with 10 trials/task for narrow or 5 for broad. For stage 1, use `--task-ids 3`; for stage 2, use `--task-ids 3 8`. For a single broad task, pass its language through `--tasks`.

For LoRA checkpoints select `--config libero_lora` or `--config libero_broad_lora`; for GRPO use `--config libero_grpo_lora`. The retained baseline sequence wrappers keep their original evaluation defaults, so set seeds/trials explicitly for a comparison across methods. No benchmark scores are generated by setup or CPU tests.
